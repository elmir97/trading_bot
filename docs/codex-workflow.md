# Работа с Trading Journal через Codex

Дата подготовки: 30.10.2026. Исходный архив и настройки Claude сохранены.

## Что перенесено

- `AGENTS.md` — основной вход для Codex: источники, порядок работы,
  архитектура, проверки и правила операций с продом.
- `.codex/config.toml` — лимит проектных инструкций 32 КиБ; AGENTS меньше
  лимита. Модель, аккаунт и разрешения клиента не переопределяются.
- `docs/codex-context.md` — важные решения, актуальная очередь, карта кода,
  разделение кода в ветке и кода на сервере, известные ограничения источников.
- `docs/codex-validation.md` — что действительно проверено в этой среде.

`CLAUDE.md` не удалён и не переименован. Его 88 КБ нельзя просто считать
автоматически загружаемым контекстом Codex с обычным лимитом 32 КиБ:
краткий AGENTS направляет к нужным разделам. Конфигурация `.claude` содержит
пустой allow-list; отдельных MCP, hooks и агентов в ней не обнаружено.

Codex читает AGENTS в начале сессии; после добавления этих файлов в уже
открытый локальный клиент начать новую сессию. Официальное описание:
https://learn.chatgpt.com/docs/agent-configuration/agents-md

   Если проект перемещён, использовать его реальный путь. Этот комплект
   не устанавливает клиент Codex на чужом компьютере и не авторизует его.
   Использовать обычный вход клиента, а не ручное копирование токенов.
3. Первое поручение:

   > Прочитай AGENTS.md и docs/codex-context.md, актуальный верх handoff и
   > операционные разделы CLAUDE.md. Проверь ветку, HEAD, локальные правки,

Открывать внешний каталог `trading` вместо `trading_bot` нежелательно:

## Интерпретатор и тестовые переменные на Windows

Исходное проверенное окружение:

```powershell
$py = 'C:\Users\vladz\venvs\trading_bot-312\Scripts\python.exe'
& $py --version
& $py -m pip check
```

Ожидается Python 3.12. Если окружение отсутствует, сначала создать его
доступным CPython 3.12 вне OneDrive/репозитория и установить
`requirements-dev.txt`. Если изменились пины, обновить зависимости до гейта:

```powershell
& $py -m pip install -r requirements-dev.txt
```

Для отдельной тестовой БД, без локального `.env`:

```powershell
$env:DATABASE_URL = 'postgresql+asyncpg://test:test@localhost:5432/trading_bot_test'
$env:BOT_TOKEN = '0:codex_local_test_only'
$env:ENCRYPTION_KEY = & $py -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
$env:TRADING_EXECUTION_ENABLED = 'true'
$env:BINGX_TRADING_MODE = 'demo'
$env:EXEC_DRY_RUN = 'true'
$env:EXEC_OPEN_DRY_RUN = 'true'
$env:EXEC_ALLOW_LIVE_MODE_ORDERS = 'false'
$env:EXEC_OPEN_ALLOW_LIVE = 'false'
$env:PYTHONUTF8 = '1'
```

Адрес здесь — только тестовый, не URL рабочей БД. PostgreSQL 18 на исходном
ПК был установлен как `postgresql-x64-18`, роль и БД уже созданы. Перед
использованием убедиться, что это по-прежнему так. Не заменять тестовую
БД продом и не выгружать секреты сервера ради тестов.

**Миграции:** для уже подготовленной БД сначала только проверить `alembic
current`/`heads`. Для новой, заведомо локальной `trading_bot_test` применить
миграции отдельно; обычная проверка среды не должна автоматически выполнять
`upgrade head` по произвольному DATABASE_URL.

## Память и границы переноса

Важная информация сохранена в **файлах проекта**, а не оставлена только
в истории переписки. Новая сессия с этим репозиторием начинает с AGENTS и
дочитывает контекст по ссылкам. ZIP нужно сохранить вместе с исходниками
или добавить новые файлы в Git после требуемых проверок.

Сам по себе новый чат без этих файлов не гарантирует доступа к ним.
История и авторизация Claude Code не становятся историей и авторизацией
Codex автоматически. Конкретные секреты и доступы подготавливаются в том
клиенте/окружении, откуда действительно будут выполняться операции.
