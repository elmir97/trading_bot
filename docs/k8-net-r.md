# К8 — плановый RR и фактический R нетто

Локальная реализация 30.10.2026. К8 не включён в подготовленный ноябрьский
деплой. На проде не применялся; сервер и биржа в этой работе не проверялись.

## Контракт

`trades.risk_reward` означает только плановый RR. Журнал записывает его при
открытии и больше не заменяет результатом выходов. Потерянный план старых
закрытых сделок неизвестен: его не восстанавливаем по тейку или итоговому R.

Фактический R не хранится. `app/trading/realized.py` возвращает
`RealizedResult(value, reason)` при чтении. Модель Trade, карточка сделки,
снимки статистики и загрузчик анализа используют этот расчёт. Неизвестное
значение — `None` с причиной; среднее исключает его, сохраняя подпись N из M.

Минимальный доказуемый набор: один подтверждённый ENTRY, явно сохранённый
`initial_stop_loss` с убыточной дистанцией, положительные цены/объёмы и
подтверждённые EXIT, не предшествующие входу. Выходов может быть несколько.
Суммарный выход не превышает вход. Несколько ENTRY — «Недостаточно данных
для определения базы риска»: это не утверждение о доказанном доборе, fills
одного первоначального ордера здесь также не объединяются догадкой.

Начальный стоп нового ручного/ботового открытия сохраняется сразу. Для
старых записей отсутствие initial_stop_loss означает неизвестный R: текущий
stop_loss его не заменяет. Trade.risk_stop с прежним fallback остаётся только
в существующих оценках карточек действий и прочих путях вне фактического R К8.
К8 не восстанавливает отсутствовавшую историю стопов или первоначальных входов. Начальный стоп
без убыточной дистанции даёт неизвестный R, а не abs() и не ноль.

Обозначения: d = +1 LONG / -1 SHORT; E, Qe — единственный вход; S0 —
начальный стоп; Qx — сумма закрытого объёма; Fe — комиссия входа;
Fx — сумма комиссий выходов. Тогда:

```text
u = d * (E - S0), требуется u > 0
gross = sum(d * (exit.price - E) * exit.quantity)
entry_fee_closed = Fe * Qx / Qe
R_net = (gross - entry_fee_closed - Fx) / (u * Qx)
```

Положительная нормализованная fee — расход, отрицательная — рибейт;
подтверждённый ноль допустим, неизвестная комиссия не становится нулём.
Decimal полной точности, округление только при отображении. Комиссии
в числителе, гипотетическая комиссия стопа не добавляется в знаменатель.
Пример: вход 10 @ 100, S0=90, Fe=1, выход 5 @ 110 с Fx=0.5:
(50 - 0.5 - 0.5) / 50 = 0.98R закрытой части. Остальная входная комиссия
относится к оставшемуся объёму. Итоговая статистика включает только CLOSED.

Карточки действий по-прежнему показывают оценку по mark и оценочной комиссии,
а карточка закрытой сделки — результат исполнений. Это разные моменты
наблюдения. К8 не меняет риск отправки ордеров, правила исполнения и лимиты.
Исторические сохранённые PnL/fees не пересчитываются миграцией; прежний
агрегат PnL частично открытой сделки не является источником нового R.

## Миграция c8a030202610 (после 919ae8ad384e)

Upgrade работает целиком в PostgreSQL, в одной транзакции, с блокировкой
trades/trade_fills. Внешний архив для него не нужен.

- Добавляет `legacy_risk_reward NUMERIC(12,4)` и `k8_legacy_row BOOLEAN NOT NULL`.
- Копирует исходный RR без пересчёта и ставит true ВСЕМ существующим строкам,
  включая исходный NULL. Серверный default для новых строк — false.
- В актуальном поле сохраняет только открытый подтверждённый план из пути
  MANUAL/BOT/SIGNAL_EXECUTION с одним ENTRY, без EXIT и exit_price.
  Остальные актуальные RR становятся NULL, исходник остаётся в legacy.
- Fills, PnL, fees, стопы и остальные исторические поля не меняет.

Новые строки с legacy=NULL/false отличаются от старых NULL/true. Дата,
последовательность ID и знак RR не используются как граница миграции.

## Локальная репетиция и rollback

Подготовка отдельного явного серверного режима `--k8`, его изоляция, архивы,
проверки и команды будущего запуска: [k8-server-rehearsal.md](k8-server-rehearsal.md).
Это не разрешение на серверный запуск; локальный CLI сохраняет ограничения ниже.

Только отдельная локальная БД `trading_bot_test`, остановленные писатели и
тестовые переменные процесса, как в CLAUDE.md. Не создавать .env. Команды
выполнять указанным там Python 3.12. Скрипт специально отказывает другому
имени БД и хосту, кроме loopback. Продовый запуск этим документом не разрешён.

Обычный upgrade:

```powershell
& $py -m alembic upgrade c8a030202610
```

Перед любым откатом нужен свежий полный дамп тестовой БД по операционному
регламенту. Архив ниже сохраняет RR и доказательства сопоставления строк;
он не заменяет полный дамп. Путь должен быть постоянным, вне репозитория,
уникальным для каждого цикла и доступным только владельцу.

```powershell
& $py -m scripts.k8_rollback downgrade 'C:\path-outside-repo\k8-cycle-1.json'
```

Скрипт под блокировкой экспортирует RR, legacy, флаг границы, ID и отпечатки
строк/исполнений. Не экспортирует notes, ключи, ответы биржи или токены.
Файл создаётся эксклюзивно (существующий не перезаписывается), fsync,
SHA256 содержимого и чтение обратно проверяются ДО downgrade. На Windows
закрытый доступ к каталогу обеспечить ACL: POSIX mode 0600 не заменяет ACL.

Для старых строк downgrade точно возвращает legacy, включая NULL. У новых
открытых без выходов остаётся план; у новых с выходами/не OPEN актуальный RR
очищается, чтобы прежний код не принял план за результат. Затем новые
колонки удаляются. Обычный `alembic downgrade` без проверки архива отказывает.

Возврат на К8 — два явных шага:

```powershell
& $py -m alembic upgrade c8a030202610
& $py -m scripts.k8_rollback restore 'C:\path-outside-repo\k8-cycle-1.json'
```

Сначала обычный upgrade консервативно классифицирует все текущие строки.
Restore проверяет формат, SHA256, имя БД, уникальность ID, ревизию и
отпечатки ВСЕХ архивных строк ДО первой записи. Отпечаток включает поля
сделки (без RR-колонок и updated_at) и все исполнения с ID. Дополнительно
проверяются legacy после нового upgrade и точное актуальное значение, которое
должен оставить обычный upgrade. Конфликт очистки ненулевого плана в NULL
также отклоняется.
Изменение/удаление строки, изменение исполнения или конфликт плана — отказ
и откат транзакции целиком. Не применять архив вручную поверх изменений.

Для неизменившихся архивных строк возвращаются план, legacy и исходный флаг
границы. Строки, созданные старым кодом между downgrade/upgrade и отсутствующие
в архиве, остаются классифицированными обычной миграцией. Каждый следующий
откат требует нового архива. Если после отката строки менялись, автоматическое
восстановление отказывает: нужен отдельный разбор данных и сохранённый дамп.

## Ограничения и отдельное расширение

- Доборы и несколько ENTRY пока не поддержаны; цены всех входов не усредняются
  ради подмены исходной базы.
- Нормализация BingX не менялась. Живые фикстуры LINK/SOL подтверждают
  отрицательный raw commission как расход. Вся история из-за abs() не исключается.
  Исследование настоящих рибейтов/положительного raw commission — отдельно.
- Исторический план не восстанавливается из других полей или execution_orders.
- Скрипт rollback сейчас намеренно ограничен локальной тестовой БД. Для
  будущего продового К8 отдельно согласовать репетицию копии, процедуру и доступ.
  Обычный путь scripts/rehearse_migration.sh не заменяет архивную процедуру К8.
  Для изолированной копии подготовлен отдельный явный --k8; серверный запуск
  ещё не выполнен. Продовый rollback CLI не добавлен.
- К8 с миграцией остаётся вне ноябрьского деплоя подготовленного кода d2b082d.
