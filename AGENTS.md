# Postfactum / Trading Journal — инструкции для Codex

## Назначение и источники

Это личный Telegram-бот `@postfactumTrade_bot` и Telegram Mini App для журнала,
риск-менеджмента, открытия и управления фьючерсными позициями BingX. Один
пользователь. Сигналы и поиск торгового преимущества удалены 02.10.2026; не
восстанавливать их по старому README или старому ТЗ.

В начале новой сессии:

1. Прочитать `docs/codex-context.md`, верхнюю актуальную часть `docs/handoff.md`
   и `docs/codex-workflow.md`. Даты в handoff идут от новых к старым; архивные
   «читать первым» не отменяют более поздних записей.
2. Прочитать `CLAUDE.md`: локальный прогон, линт, скрипты и конвенции. Это
   подробный общий операционный регламент, он сохраняется и для Claude Code.
   Перед работой с сервером дополнительно прочитать его разделы деплоя и чек-апа.
3. Проверить `git status --short --branch`, текущий HEAD и diff. Не стирать
   незакоммиченные правки владельца и не делать reset/clean ради «чистоты».
4. По задаче читать `docs/open-trade-plan.md`, `docs/miniapp-plan.md`,
   `docs/execution-stage-15.md`, `docs/architecture.md` и соответствующий код.
   README, начальные статусы планов и архитектурная сводка частично устарели.

Приоритет: текущая инструкция владельца → последние решения в handoff → этот
файл и актуальный операционный регламент → предметная спецификация → история.
Состояние сервера в документах — последнее наблюдение, перед деплоем сверять.
Не выдавать исторические тестовые цифры или прод-состояние за свежие измерения.

## Порядок работы

- Общаться по-русски. Объяснять результат, затронутые файлы, проверки и блокеры.
- Для задачи более чем в двух модулях сначала дать план по файлам. Выполнять
  уже порученную локальную работу без повторных согласований каждого файла.
- Изменения делать небольшими и проверяемыми; реализацию из очереди не начинать
  только потому, что она записана в документации. Обновлять handoff после
  существенной работы: что сделано, что проверено, что не на проде, следующий шаг.
- Перенос среды разработки с Claude Code на Codex не означает смену LLM внутри
  продукта: `AnthropicClient` и его конфигурацию не менять без отдельной задачи.
- Не переносить в Codex токены из `auth.json`, браузера, переписки или Claude.
  Использовать штатную авторизацию клиента. Разрешения клиента наследовать;
  не включать обход подтверждений или sandbox ради этого проекта.

## Архитектурные ограничения

- Python **3.12**, зависимости — точные пины `requirements-dev.txt` и
  `requirements.txt`. Образ — `python:3.12-slim`.
- aiogram / FastAPI → общее ядро исполнения → биржа и журнал. В обработчиках,
  API-маршрутах и JS не создавать второй расчёт риска или исполнения.
- Фронт — обычные ES-модули в `miniapp/`, CSS, локальные шрифты и
  Lightweight Charts 5.2.1. Сборки npm нет. CSP не ослаблять; библиотеку и SDK
  вендорить с сохранением лицензий и контрольных сумм существующих тестов.
- Цены, деньги, объёмы — Decimal полной точности. Форматирование —
  `app/bot/formatting.py`; округление явно, обычно `ROUND_HALF_UP` при выводе.
  Шаг цены для отправки — только `app/execution/price_step.py`. Округление не
  должно увеличивать выбранный долларовый риск. Объём округляется вниз.
- Настройки — `get_settings()`, в тестах — явный `Settings(...)`, новые поля с
  безопасными дефолтами. Молчаливый fallback вместо известного отказа — баг.
- Состояние исполнения хранится в PostgreSQL. PENDING и детерминированный cid
  коммитятся **до HTTP**; UNIQUE cid, условные переходы статуса и Redis-лок
  защищают совместную работу бота и API. Таймаут → поиск по cid и восстановление;
  не отправлять вход автоматически повторно.
- Стоп обязателен. Отсутствие защиты после входа → предусмотренный ядром
  запасной стоп, затем аварийное закрытие и ALARM. Не обходить эти ветки.
- Счёт DEMO/LIVE, пользователь, сторона и positionId участвуют в привязке.
  Не связывать сделки и действия только по символу. При расхождении выбранного
  и разрешённого счёта нужен отказ, а не тихая подмена.
- Тип и уровни SL/TP брать из **openOrders**, запрос по cid/orderId — для
  статуса. Отсутствие ордера подтверждать историей **и** открытыми ордерами.
  Формы BingX брать из проверенных фикстур; свежую разведку отдельно согласовать.
- Снятие строк SL/TP централизовано в `app/execution/settle.py`. Статус
  `CANCELLED` с двумя L; `cancel_source=EXCHANGE` только по доказательству,
  неизвестный источник — NULL. Неполная история не доказывает отсутствие.
- Начальный стоп не подменять текущим. Стоп не с убыточной стороны входа не
  превращать в положительный 1R через `abs()`; показывать «R не определён».
  Решение К8 о едином R нетто ещё требует отдельного разбора данных.
- Не менять механизмы initData/владения/аудита/лимитов запросов. Аудит должен
  записаться до действия; сбой аудита — отказ, без отправки на биржу.

## Локальные проверки

- На исходном Windows-ПК Docker не работает: Docker Desktop и compose-профиль
  test там не запускать. Там используется нативный PostgreSQL 18 и Python из
  `C:\Users\vladz\venvs\trading_bot-312\Scripts\python.exe`.
  В другой среде сначала проверить доступность инструментов; старые пути не
  считать существующими. Подготовленная среда этой сессии описана в workflow.
- Локально `.env` не создавать. Тестовые переменные задавать окружением
  процесса. Только отдельная БД **trading_bot_test**, с тестовыми учётными
  данными; BOT_TOKEN — `0:...`, ENCRYPTION_KEY — свежий Fernet на прогон.
  `TRADING_EXECUTION_ENABLED=true`, контур demo; разрешения LIVE выключены.
- pytest, smoke, mypy, ruff — **по очереди**. Полный pytest — частями в переднем
  плане; union списков файлов = collect, сумма passed = collect. Перед каждой
  частью показать доступную RAM; меньше 300 МБ — остановиться и сообщить.
  Не оставлять автономный оркестратор частей после завершения сессии.
- Команда pytest: `python -m pytest --capture=sys ...`. Гейт зелёный только
  при exit 0, **0 failed и 0 skipped**. Без БД полноценного гейта нет. Сбор
  тестов, синтаксическая проверка и отдельный набор тестов его не заменяют.
- Smoke: `python -m scripts.smoke_check` **дважды подряд**, без ручной уборки.
  Сеть должна оставаться нулевой. Новый метод биржи на пути карточки/«Да» —
  новая заглушка smoke в той же правке. 424242 — id только smoke; 434343 — стенда;
  тестовые id выделять через существующую фикстуру, не трогать пользователя стенда.
- Базовые команды: `python -m ruff check .`,
  `python -m ruff check . --statistics`, `python -m mypy app`.
  Существующий долг ruff/mypy не выдавать за чистый прогон и не скрывать
  исключениями. Сравнивать одинаковую команду и периметр на базе и после правки.
- При изменении логики/фронта — содержательные мутации и нужные браузерные
  сценарии по `CLAUDE.md`. База сначала зелёная; CAUGHT только падением проверки.
  NameError/ImportError/SyntaxError → BROKEN_MUTANT; сбой SDK/обвязки →
  INCONCLUSIVE. В итоговом принятом прогоне оба счётчика = 0, MISSED = 0.
- Стенд и Chrome допустимы вместе для проверки фронта; **pytest одновременно
  с ними не запускать**. Перед pytest снять их деревья процессов и проверить
  освобождение 8765. Новый сценарий — три зелёных прогона подряд.
  Windows-команды taskkill не считать переносимыми на Linux без проверки.
- Перед push кода — полный гейт. Исключение владельца: только `docs/` и
  `*.md` после последнего кода с зелёным гейтом; доказать это списком diff.
  `.codex/config.toml` — конфиг, поэтому под исключение документации не попадает.
  Не коммитить через пайп, который скрывает exit pytest. После разрешённого
  коммита — push по регламенту, если доступ действительно есть; сбой сообщать.

- Деплой/откат/репетиция — строго по текущему `CLAUDE.md`: чек-ап, свежие дамп
  и снапшот (umask 077, права 600), **проверенный rollback-тег до build**, md5
  к коммиту; `git -c core.autocrlf=false archive`. У bot и api общий образ:
  после build пересоздаются оба; Caddy — только если изменился его конфиг.
- Миграция прода: репетиция на копии, SQL из нового образа в offline-режиме,
  явное разрешение владельца, затем применение и проверки. Неожиданная
  миграция/ошибка — остановиться. Downgrade должен работать; его CHECK писать
  в хранимой форме PostgreSQL согласно конвенциям `CLAUDE.md`.
- `.env` и `docker-compose.override.yml` прода — server-only, не перезаписывать
  архивной копией. Секреты не печатать, не копировать в документы и не коммитить.
  Нельзя менять рабочий ENCRYPTION_KEY: сохранённые ключи перестанут читаться.
- Обход авторизации и фейковая биржа — только `scripts/miniapp_dev.py`,
  только loopback и тестовая БД. Не переносить их в `app/` и не публиковать стенд.
