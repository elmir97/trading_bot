# Trading Journal Bot

Персональный Telegram-бот для ведения торгового журнала, статистики,
риск-менеджмента и поиска сетапов на фьючерсах BingX.

**Статус: этап 1 из 14** — каркас проекта, конфигурация, логирование,
подключение к БД, Docker. Торговый журнал появится на этапе 4.

## Требования

- Python 3.12+
- PostgreSQL 16
- Docker и Docker Compose (для запуска на VPS)

## Быстрый старт

```bash
cp .env.example .env
python -m scripts.generate_key      # вставить результат в ENCRYPTION_KEY
```

Заполнить в `.env`:

| Переменная | Где взять |
|---|---|
| `BOT_TOKEN` | @BotFather |
| `ALLOWED_TELEGRAM_IDS` | @userinfobot — свой числовой ID |
| `POSTGRES_PASSWORD` | придумать; продублировать в `DATABASE_URL` |
| `ENCRYPTION_KEY` | вывод `scripts/generate_key.py` |

Запуск:

```bash
docker compose up -d --build
docker compose logs -f bot
```

Локально, без Docker:

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
# DATABASE_URL с host=localhost
python -m app.main
```

## Проверка

1. `docker compose ps` — оба контейнера `running`, postgres `healthy`.
2. В Telegram: `/start` → приветствие.
3. `/ping` → время ответа БД в миллисекундах.
4. `docker compose logs bot` — есть `Соединение с PostgreSQL установлено`,
   и **нигде не видно токена бота**.
5. `pytest` — 13 тестов проходят.

Если написать боту с чужого аккаунта — придёт «Доступ ограничен»,
а в логе появится предупреждение с чужим ID.

## Структура

```
app/
├── bot/          Telegram: handlers, keyboards, middlewares, FSM
├── core/         config, logging, security — без бизнес-логики
├── database/     models, repositories, session
├── exchanges/    абстракция биржи + BingX (этап 7)
├── market/       свечи, рыночные данные (этап 8)
├── trading/      журнал, риск, статистика (этапы 4–6)
└── analysis/     индикаторы, сетапы, сигналы (этапы 9–10)
```

Слои: `handlers → services → repositories → database`.
Хендлеры не содержат бизнес-логики, домен не знает про aiogram и SQLAlchemy.

## Архитектурные решения

- **Decimal, не float** для всех цен и денег.
- **Плечо не входит в формулу PnL**: `(exit − entry) × qty × direction − fees`.
  Плечо влияет только на маржу и лимиты размера позиции.
- **`trade_fills` как источник истины**: агрегаты в `trades` пересчитываются
  из исполнений, чтобы частичные входы и выходы не потребовали переписывания.
- **Все секреты в SecretStr**, фильтр логов вырезает их как последний рубеж.
- **Биржевые ключи шифруются Fernet** перед записью в БД.

## Безопасность

Ключи BingX — **только read-only**, без прав на торговлю и вывод средств,
с привязкой к IP сервера. Read-only ключи у BingX бессрочны; ключи с правами
торговли без привязки к IP удаляются после 14 дней неактивности.

Файл `.env` в git не попадает. `ENCRYPTION_KEY` менять нельзя: после смены
сохранённые биржевые ключи станут нечитаемыми.

## Дисклеймер

Система анализирует данные и считает показатели. Она не предсказывает
рынок и не гарантирует результат сделки. Автоматическое исполнение
ордеров не реализовано и в текущий контур не входит.

## Миграции

```bash
alembic upgrade head          # применить
alembic downgrade -1          # откатить последнюю
alembic revision --autogenerate -m "описание"   # после изменения моделей
```

Первая миграция создаёт 9 таблиц. Проверена на применение и откат.
